# 专属队伍轴模块

该目录提供高于单角色出招表和通用切人优先级的队伍级控制层。

## 接管边界

队伍轴命中后，`AutoCombatTask` 不再调用 `BaseChar.perform()`，因此不会触发：

- 单角色内置或自定义出招表；
- `switch_next_char()` 通用优先级；
- 协奏元素环选人。

队伍轴仍复用现有的技能检测、终结技检测、协奏入场检测、切人确认和战斗结束检测。

## 内建轴

复制 `axes/NanallyZeroJiuyuanHotoriAxis.py`，然后只需要修改：

1. `team_signature`：按固定槽位填写四个 `builtin_key`；
2. `run_opening()`：只执行一次的开场轴；
3. `run_cycle()`：每次调用执行一轮完整循环轴。

注册表会自动扫描 `axes` 目录，不需要再编辑中央列表。多个轴同时匹配时，`priority` 数值较高者优先。

## 自定义轴

在“角色中心 → 固定轴”中可以直接新建自定义固定轴。自定义轴保存以下字段：

1. 轴名；
2. 轴简介；
3. 轴内容；
4. 保存时当前固定队伍的四个内置角色槽位。

轴内容复用角色出招表语法，但所有角色动作命令需要加位置前缀：

- `p1_`：固定队伍 1 号位；
- `p2_`：固定队伍 2 号位；
- `p3_`：固定队伍 3 号位；
- `p4_`：固定队伍 4 号位。

示例：

```text
p1_skill, p2_ultimate, p3_l_click(2), p4_wait(0.5)
```

`if_` 作为全局控制命令保留原名，条件和动作同样使用位置前缀：

```text
if_(p1_ultimate, p1_skill), if_(p2_skill(0.5), p3_l_click(2))
```

## 界面与安全开关

在“角色中心 → 固定轴”中选择并启用方案。启用前必须满足：

1. “队伍管理”中已启用四人固定队伍；
2. 四个槽位均选择了内置角色代码；
3. 槽位顺序与固定轴的 `team_signature` 完全一致。

固定队伍未启用、固定轴已停用或当前队伍不匹配时，程序会完整回退到原有战斗逻辑。

当前娜娜莉、零、九原、浔轴已实现双娜娜莉站场的完整记录循环，包括协奏校验、零 Q 可用性分支、浔头像进度上涨判别和动作失败保护。

## 跟随作者版本更新

最稳妥的方式是把整个功能保存为自己分支上的一个独立提交：

1. 主分支只跟踪作者代码；
2. 建立 `my-team-axis` 分支；
3. 将 `src/team_axis`、测试和 `AutoCombatTask.py` 的小型接入改动放在同一个提交中；
4. 作者更新后，把这个提交 rebase 或 cherry-pick 到新版代码上。

真正与作者文件重叠的代码只有 `AutoCombatTask.py` 中的接入点。其余队伍轴文件均在独立目录内，通常不会产生合并冲突。
